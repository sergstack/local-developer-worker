# Tool contracts

Every command consumes one JSON object and returns a `ToolResult` v1.0.0. Tool failures use a visible status (`partial`, `unsupported`, `invalid_input`, `policy_blocked`, `timeout`, or `internal_error`) rather than an empty success response. Source-linked fields include a source identifier, raw SHA-256 and source range when applicable.

`ldw doctor` includes `data.test_status_reminder`, which directs callers to establish pass/fail through `ldw test parse` rather than interpreting runner output directly.

`ldw doctor` additionally reports a privacy-safe optional `local_inference` capability state. It distinguishes policy disabled, incompatible configuration, unavailable verified runtime, and a missing configured model without exposing the concrete model name or changing the environment. It does not start Ollama, install packages, or pull models.

`ldw log parse` preserves one record per input line. `ldw log cluster` retains the legacy v1 full-accounting contract. `ldw log process` uses `semantic_log_grouping_contract: 2`: deterministic code assigns a disposition to every Stage A event, sends only bounded candidates to the loopback model, validates candidate-only IDs, and reconciles final accounting. Model transport requires payload `semantic: true` unless policy explicitly sets `[semantic].automatic_routing = true`; the absent/false default disables threshold/signature routing. Groups remain `model-derived` candidates; raw provider responses are never emitted or persisted. `ldw test parse` only reports observed outcomes. `ldw git facts` runs read-only Git commands. `ldw files inventory` records paths and metadata without emitting sensitive contents. Optional `semantic_candidates` remain separate from observed files, commands, and tests.

`ldw context pack` payload contract `2.0.0` requires an explicit allowed repository root at the CLI boundary. Each included path has a selection reason, evidence source, and explicit/deterministic/candidate/unknown relevance status; each considered exclusion has a controlled reason and policy rule. `mode=expand` requires the previous full ToolResult and matching run ID, an explicit missing-context reason or deterministic trigger, and adds only bounded requests. It returns `added_files` separately from reusable prior files, records byte measurements (token counts remain unmeasured), limits expansion depth, and repeats root, symlink, sensitive, ignored, binary, generated, and limit checks. Legacy context keys remain readable.

`ldw context compact` contract `1.0.0` accepts only a caller-supplied preservation set and optional candidate summary. It preserves all declared critical state exactly, marks summaries non-authoritative, records dropped/superseded items with reasons and byte measurements, never invokes a model, and returns `partial` rather than assuming success when preservation or measurement is incomplete.

`ldw offload execute` contract `1.0.0` is defined by `offload_execution_input.schema.json` and `offload_execution_data.schema.json`. It consumes a caller-owned policy envelope; it does not infer eligibility or maintain an AI-OS task-policy registry. The envelope preserves `task_class`, `risk_floor`, `offload_mode`, `verification_kind`, `fallback_policy`, and the exact `policy_revision` in every routed result. Local output is schema-bounded, `candidate_only`, and source-linked to its local-model ToolResult. Optional paired `context_bytes_before`/`context_bytes_after` values produce only an observed byte delta. A failed or disabled local route may consume only an explicitly supplied successful deterministic ToolResult, then invoke a caller-authorized frontier route, or fail visibly when frontier fallback is forbidden or unavailable. Runtime, requested-model, and policy-blocked capability states remain distinct. Ollama remains optional and the command never installs, starts, or pulls it.

`ldw offload evaluate` contracts `1.0.0` and `1.1.0` are defined by `offload_effect_study_input.schema.json` and `offload_effect_study_data.schema.json`. It is a deterministic analyzer of caller-supplied matched measurements, not a route runner. Its exact allowlist accepts only opaque match IDs, abstract classes, controlled statuses/codes, policy hashes, and aggregate measurements; raw tasks, paths, prompts, and model/provider responses are rejected. V1.1 adds matched environment/acceptance conditions and null-safe task-journey observations for expansions, compaction/rereads, tool calls, corrections, preliminary attempts, fallback, escalation, route/profile, and controlled overhead reasons. It never promotes a route: its sole positive verdict is `READY_FOR_AI_OS_REVIEW`, with `promotion_authority: ai_os_only`.

`ldw evidence build` payload contract `2.0.0` preserves only supplied evidence with applicable source tool/run/path/event/test/Git lineage and controlled origins. Test status authority belongs only to `ldw test parse`; Git authority belongs to `ldw git facts` or explicit user-provided evidence; model groups remain candidates. Missing tests, questions, and next bounded action stay visible in resumable state. Legacy evidence keys remain readable.

`ldw review build` contract `1.0.0` is defined by `review_build_input_v1.schema.json` and `review_package_v1.schema.json`. It accepts only a bounded declared scope plus opaque provenance references and required-check statuses; raw repository content, logs, prompts, and full evidence packages are rejected. The caller-retained evidence manifest remains authoritative. The derived `ReviewPackage` selects a deterministic `local`, `contract_change`, `cross_boundary`, or `evidence_risk` profile, preserves `not_run`/`unknown` states, and has no model, rendering, mutation, root-cause, merge, or promotion authority.

`ldw review build` contract `1.1.0` is defined by `review_build_input_v1_1.schema.json` and `review_package_v1_1.schema.json`; it preserves the P0 behavior and adds only a derived evidence ledger plus optional structural contract delta. Comparison inputs are opaque contract IDs, version labels, hashes, and caller-declared field IDs. `not_applicable` and `unavailable` remain explicit; an available delta never claims compatibility, semantic equivalence, acceptance, or a review outcome.

`ldw review render` contract `1.0.0` is defined by `review_render_input_v1.schema.json` and `review_render_output_v1.schema.json`. It accepts exactly one P0/P1 ReviewPackage and `format: markdown`, validates the supplied package structurally, then returns byte-stable Markdown and its SHA-256. It reads no repository, does not write an artifact file, and makes required-check, evidence, unknown, contract-delta, and authority state visible without changing their authority. HTML/D2/SVG, MCP, model calls, mutation, review decisions, promotion, and merge remain out of scope.

`related_test` matching is intentionally limited to relative `src/` and `tests/` paths. Callers may supply `required_files` for immutable, task-specific verifier dependencies (for example a frozen fixture or schema); these are included as deterministic dependencies after the same root and safety checks. This lets a bounded initial pack retain required acceptance context without treating unrelated files as relevant.

`ldw telemetry summary` reads privacy-safe local session events. `ldw portfolio verify` reconciles all declared gate tests and action artifacts without stopping after an item failure; `--only ID` resumes one item while preserving 20 output rows. `ldw portfolio status` reports saved evidence and marks completed evidence stale when the commit or workspace fingerprint changes.

`inference_endpoint_policy` returns a normal `ToolResult`; any non-loopback or unresolved inference endpoint returns `policy_blocked` with `non_loopback_inference_endpoint`. `guarded_inference_call` pins accepted calls to the validated loopback IP. Every `log_cluster` transport, including a dependency-injected transport, requires exactly one observable local Ollama listener whose process and executable identity match before transport invocation. Missing, ambiguous, tunnel, proxy, or unverified listeners return `policy_blocked` with `local_inference_runtime_unverified`. Tests provide synthetic process observations through a private runner seam while exercising the canonical verifier. Successful metadata distinguishes `local_runtime_verified` from `physical_inference_locality: not_provable`; process inspection is not cryptographic service attestation.

`ldw ollama advise` is an opt-in, read-only local-model advisory surface. It accepts only a bounded task and uses the same canonical loopback/runtime guard as semantic clustering. It has no repository access, tool execution, or write capability. Only a strict structured advisory (`summary`, `next_actions`) may cross the boundary; invalid model output becomes `partial`, and raw prompts, envelopes, and responses are not retained.
